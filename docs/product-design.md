# Friend 桌面宠物：设计讨论记录

更新日期：2026-10-18。本文记录 grill-me 讨论结果；首轮角色对话与桌宠原型已完成本机模拟接口和 Windows 10 x64 打包验证，真实 API 与摄像头效果尚待验证。

## 1. 已确认的产品范围

- 面向公开发布，整体开源；具体许可证根据 SillyTavern 的修改与集成方式确定。
- 首版兼容目标：Windows 10 / Windows 11，x64。
- 桌面外壳采用 Electron + TypeScript 路线；暂不设置严格的安装包和内存上限，但需要测量资源占用。
- 用户自行配置 API 地址、Key 与模型；不提供统一托管 AI 服务或账号系统。
- 用户通过点击按钮或发送消息控制学习的开始与结束；此规则替换先前的“学习倒计时归零后自动进入休息”。
- 明确的用户控制指令直接执行，例如“开始学习”“结束学习”；“等会儿该学习了”等含糊聊天表达不立即改变状态。控制指令来自用户输入，角色回复不作为操作授权；含糊但疑似操作请求的表达可提供确认入口。
- 计时器记录实际学习时长，不以固定时长到期自动结束学习。
- “结束学习”表示结束当前学习段并进入休息，停止自动观察，按已配置渠道主动开场一次；保留学习任务供下一段继续。结束本段后先归档再清空聊天小窗，休息交流归入刚结束的段；“结束任务”结束整个任务、清空小窗并立即将本段计时归零。下一次开始建立新任务。
- 每次进入休息时主动开场一次，结合学习情况鼓励并提供可选话题；用户未回应时保持安静。
- 学习期间允许自由聊天。
- 学习结束后的休息聊天通过 Telegram Bot 在手机上进行；每位用户自行创建 Bot 并配置 Token，软件提供创建与私聊绑定引导。
- 允许从手机按钮或消息启动学习，并同步电脑端状态；原休息倒计时结束通知方案需随手动控制方式重新确认。
- 新学习段启动后恢复自动观察，并重置该段手机/电脑娱乐提醒额度、提醒阶段和聊天轮数；等待开始时不提前重置或恢复观察。
- 今日热点新闻分享，以及按上午行为调整提醒、在中午集中鼓励，作为后续扩展。

### Telegram 接入

- 已确认用户自带 Bot；建议绑定用户自己的 Telegram 私聊，由桌面程序通过长轮询接收消息，无需公网入站服务。
- 手机消息交给同一个 SillyTavern 角色与会话处理，复用当前学习摘要；Telegram 作为消息入口，不另建角色记忆。
- Telegram 消息经过其平台传输与保存；本机保存自身会话与长期摘要，不等于 Telegram 平台不留存聊天。
- 本机承担生成与消息收发时，电脑必须保持运行且能连接 Telegram 和模型服务；睡眠、休眠或程序退出期间无法实时回复。
- Telegram 休息聊天期间默认请求避免电脑自动睡眠，用户可以关闭；显示器可以熄灭，摄像头与桌面自动采集保持停止。
- 休息及等待用户开始学习期间继续保持电脑清醒，直到进入下一段学习或用户手动结束任务；进入学习时切换到学习阶段的保持清醒设置，手动结束任务时释放请求。用户主动睡眠或休眠时仍按系统暂停规则处理，此保持清醒选项仍可关闭。
- Telegram 角色回复提供文字与可开关的语音消息，沿用用户配置的 TTS 和角色音色；只朗读角色说话内容，手机端由用户点击播放。TTS 未配置或失败时照常发送文字。
- 若用户关闭保持清醒选项或主动让本机睡眠，则睡眠期间不能实时接收手机开始指令。
- 用户未配置 Bot 或 Telegram 连接失败时，回退到电脑端休息聊天，沿用同一角色与会话。
- 建议回退时只提示一次；已成功发送的开场不重复发送，连接恢复后不补发过时提醒。消息去重、失败重试与跨端同步细节需要在实现中验证。

## 2. 感知与行为判断

- 学习计时运行时，每 30 秒进行一轮视觉分析；采集所有显示器以及用户选定的摄像头。
- 仅在学习期间自动观察；暂停、休息或任务结束后停止自动采集。
- 锁屏时继续学习计时与摄像头观察，停止桌面截图；锁屏本身不视为学习暂停。
- 实际进入睡眠或休眠时，暂停学习计时、观察与提醒；保留同一学习段已用提醒额度和聊天轮数。
- 锁屏后摄像头采集能力需要通过 Windows 10/11 与实际设备验证；断流按观察中断处理，不把旧画面当作当前观察。
- 因系统睡眠或休眠自动暂停的学习任务，唤醒后自动继续，保留累计已学习时长、本段已用提醒次数与聊天轮数；行为提醒的当前等待阶段重新计时，不累计睡眠期间的时长。
- 唤醒自动继续只恢复系统睡眠导致的暂停，不恢复用户手动暂停或已结束的任务；采集恢复失败时按观察中断规则处理。
- 学习期间默认临时请求系统避免因无操作而自动睡眠，用户可以关闭此选项；允许显示器熄灭，暂停、休息或任务结束后释放请求。用户主动睡眠或休眠时仍按上述暂停与唤醒规则处理。
- 桌面截图与摄像头画面在用户开启相应权限后，都允许上传到用户配置的云端 API。
- 不采用手机与电脑屏幕联动作为首版方案。
- 摄像头主要观察用户身前的桌面、纸张、双手和手机；接受机位调整与外接摄像头。
- 首次设置提供机位预览与校准，检查关注区域是否可见、内容是否清晰。
- 没有摄像头或摄像头不可用时，允许仅桌面观察模式；不推断未观察到的手机和纸质学习状态。
- 电脑端采用用户规则 + AI：明确标记学习与娱乐活动，模糊情况结合任务主题和画面分析。
- 首版优先减少误提醒。观察、推断和用户确认需要区分；无法判断时保留未知。
- 持续使用手机但用途不明时，先按规则温和询问，用语遵循角色人设，不直接认定为娱乐。
- 采样只能估计行为持续时间，不能精确还原两次采样之间的行为。
- 画面被遮挡或内容不清晰不等于行为停止；视觉调用失败也不构成娱乐证据。
- 从画面拍摄时刻起超过 60 秒返回的分析结果，不用于即时提醒；判断时效以拍摄时间为准，不以响应返回时间为准。
- 新观察已确认待提醒行为停止、任务暂停或进入休息时，取消尚未发出的相关行为提醒；旧响应不能覆盖更新的行为状态。

### 2026-10-14：应用规则优先的节省调用方案（讨论中，尚未实现）

- 用户提出：先读取当前使用的应用，由用户把常见应用标记为学习、游戏/娱乐或混合用途；混合用途再详细判断。拟替换电脑端每 30 秒无条件上传全部屏幕的策略。
- 建议在本机获取前台窗口所属进程、可执行文件标识与窗口标题，通过切换事件或短间隔轮询更新，不调用模型。正在后台运行、最小化或仅开启启动器不等于正在玩游戏。多屏非前台活动仍需按可见性、任务与必要画面分析补充，不能仅依据进程列表断言。
- 用户明确标记为学习或娱乐的应用先由规则判断；学习标签仅说明电脑活动用途，不证明用户此刻专注，也不豁免摄像头观察到的手机使用。娱乐规则命中只启动原有连续计时，不立即提醒。
- 浏览器、聊天软件和其他混合用途应用，优先用用户配置的窗口标题等本机规则；未能判断时再按需截图交给 AI。普通窗口标题接口不保证能读取浏览器 URL 或页面正文。
- 在应用/标题变化或确有复核需要时调度 AI，合并短时间内的重复触发；已过期的视觉结论不能因标题未变而无限续期。即时提醒仍遵守拍摄后 60 秒有效期、更新优先及观察中断规则。
- 已标记学习的软件不能取代摄像头对手机与纸质学习的判断。摄像头是否继续每 30 秒云端分析，以及是否采用本机变化检测与定期复核，需单独明确并通过真实设备验证。
- 未标记应用的默认策略尚待确认：自动按混合用途详细判断，或先保持未知并提供分类入口。无法识别时不直接触发娱乐提醒。
- 固定每 30 秒相当于每小时 120 轮；多屏和摄像头可能每轮包含多张图片。应用识别不消耗模型 token，但真实节省比例取决于规则覆盖、未知活动、摄像头频率和复核次数，不能预先保证百分比。

### 2026-10-18：已实现前台窗口读取（0.1.1）

- 用户要求先实现读取应用及具体窗口标题。本次实现仅包括本机采集与展示，不包括应用分类、标题 AI 分析、截图或行为提醒。
- 使用自带 Windows 读取组件，通过 `GetForegroundWindow`、`GetWindowThreadProcessId`、`GetWindowTextW`、`QueryFullProcessImageNameW` 获取前台应用、进程名/PID、窗口标题和可访问的可执行文件路径。每秒轮询，不枚举后台应用作为当前使用证据。
- 默认只在学习期间读取；暂停、休息、结束任务、睡眠和锁屏时停止组件并清空当前与最近记录，继续学习/解锁时按当前学习状态恢复。提供独立关闭开关。
- 点击桌宠切回本程序后，当前窗口确实变为桌宠；界面明确展示“最近外部窗口”及采样时间，便于查看刚才 Edge 的标题，不把该历史记录标为当前前台。
- 路径受权限限制时允许部分结果，窗口切换竞态或无法取得前台窗口时输出未知。组件断流超过 5 秒，不再将旧样本显示为当前窗口。
- 结果仅保存在运行内存与界面，不写入学习/聊天记录，也不发送到对话或语音 API。普通标题读取不等于获取 URL、其他标签页、网页正文或视频播放状态。
- 用实际 Edge 和独立本机页面验证标题变化及中文/特殊字符；不据此声称已验证 B 站实际视频、全屏或画中画。系统锁屏/睡眠事件使用模拟事件测试，真实设备验证仍保留。
- 微软接口参考：[窗口标题](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindowtextw)、[进程路径](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-queryfullprocessimagenamew)。

## 3. 提醒规则


### 手机与电脑娱乐

- 每个学习段合计最多 3 次即时提醒。
- 三次提醒前的等待间隔分别为 5、10、15 分钟。
- 单一行为一直持续时，对应第 5、15、30 分钟提醒。
- 手机与电脑使用统一的连续提醒计时：从手机切换到电脑娱乐时继续累计。
- 任一来源出现有效的待提醒行为即可计时；同时出现时只计实际经过时间，不叠加两路时长。
- 确认两路待提醒行为都停止后，清零当前等待计时；该学习段已使用的提醒额度保留。
- 提醒语气跟随人设，例如调皮地询问手机用途。
- 行为判断可靠且仍在有效期内、但对话 API 生成提醒失败时，使用内置文字提醒；仍遵守提醒间隔、用途豁免、语音等待与每段最多 3 次的限制，仅实际发出的提醒占用额度。判断本身无效或不足时不借此触发提醒。
- 内置提醒按已知情况表达；手机用途未确认时使用询问用途的文字，不把“使用手机”写成已确认娱乐。
- 用户说明手机正在用于学习后，本次连续手机使用期间暂停手机提醒；确认放下后豁免结束。
- 手机提醒提供“本次在学习”纠正入口，并接受用户明确的消息解释；确认用于学习后立即应用本次手机用途豁免，取消尚未发出的相关手机提醒，不自动建立永久白名单。
- 已发出的提醒被用户纠正后，仍计入本学习段最多 3 次的额度，不返还次数；记录标记为已纠正，避免将被纠正的推断保存为已确认事实。
- 达到 3 次上限后，本学习段停止手机和电脑娱乐的即时提醒。
- 两路行为共用提醒阶段与次数；并发触发时只发送一条提醒。
- 手机用途豁免只影响手机这一路；电脑娱乐仍可触发统一提醒计时。
- 观察中断、无法确认行为时停止提醒计时；恢复有效观察后重新开始当前等待阶段，不拼接中断前后的连续时长。
- 观察中断不影响学习计时，也不清除本学习段已使用的提醒次数。

### 聊天

- 每个学习段累计交流 30 轮时提醒回去学习，仅提醒一次。
- 此规则替换之前讨论的“聊天超过 10 分钟提醒”。
- 聊天提醒单独计数，不占手机与电脑娱乐的 3 次额度。
- 当前轮数定义：用户一次发言 + 宠物一次完整回复为 1 轮；自动观察记录与后台生成不计入。
- 新的学习段重新计数；休息期间不触发学习聊天轮数提醒。

## 4. 学习内容与记忆

- 学习交流依据：任务主题 + 自动观察摘要 + 用户补充。
- 看清的内容可以形成摘要；观察到做试卷不等于读清全部题目。
- 深入讨论具体问题时，用户补充照片、文件或文字。
- 首版学习资料输入支持文字、图片、PDF、Markdown（`.md`）和 Word（`.docx` 与旧版 `.doc`），电脑端与 Telegram 均提供提交入口；两种 Word 格式均支持直接导入，格式解析或必要转换由程序处理，不要求用户提前转换。复杂排版与公式识别需要用真实样本验证。
- 建议统一资料解析流程：文字与 Markdown 解析文本，PDF 与 Word 提取文字、结构和必要的页图，扫描页和图表通过视觉分析补充；保留文件名、章节、页码或段落位置供引用。
- 用户指明章节、页码或其他资料范围时，只分析指定范围；未指明范围时分析全文。长文档按批次覆盖全篇后汇总，记录已完成范围与解析失败部分；后续对话按当前问题召回相关内容。
- Telegram 标准 Bot API 当前 `getFile` 下载上限为 20 MB；超限资料建议从电脑端导入。自托管 Local Bot API 的大文件方案可另行评估，不作为当前已确认依赖。
- 保留跨天长期摘要，包含学习主题、用户确认的难点、进展与交流偏好。
- 每段学习结束后自动生成并保存长期摘要，供休息聊天与后续学习使用；只将可确认的进展与用户明确提到的难点作为事实，不确定观察单独标注。
- 参考用户提供的酒馆助手表格插件，已静态阅读其加载入口、`AlbusKen/shujuku` 的 `spv8.9.1` 源码和外部 API 文档；表格模板、增删改、纪要合并与世界书同步可供学习记忆设计参考，尚未运行验证或决定直接内置整个插件。详见 [表格记忆参考](table-memory-reference.md)。
- 用户可以查看、纠正和删除记忆；观察推断与用户确认需要标识来源。
- 学习主题、进展和难点跨角色共享；各角色的交流记忆与约定分别保存。切换人设不自动迁移其他角色的私人交流约定，不改变当前学习段状态或提醒计数。
- 数据保存在本机，支持手动备份、导入与导出；不提供首版账号与云同步。
- 默认不留存自动采集的原始桌面截图和摄像头画面。
- 用户主动提交的图片与文档默认保存到本机资料库，提供查看与删除入口，供跨天讨论、回看题目与定位原文使用；原文件与生成的摘要、索引之间保留来源关联。
- 删除资料默认一并清理原文件、由其生成的摘要、索引和关联记忆，并同步清理用于后续角色生成的缓存或注入内容；另提供“仅删除原文件”选项，允许保留分析结果。清理范围为本程序维护的数据。
- 导出备份默认不包含 API Key。

## 5. 人设、外观与语音

- 对话核心采用 SillyTavern；安装包内置固定版本运行环境，由桌面程序管理生命周期。
- 通过保留 SillyTavern 前端上下文与桥接扩展接入角色生成流程，不能仅把其服务端视作完整的无界面对话引擎。
- 首版支持经过验证的角色卡、世界书、生成预设、桥接与选定 TTS 能力；不承诺任意第三方扩展兼容。
- 使用 2D 状态动画：待机、说话、提醒、鼓励、休息。
- 日常聊天通过点击狐狸打开聊天小窗，展示消息、输入框和学习控制按钮；高级角色卡、世界书与生成预设设置建议通过独立酒馆窗口提供。
- 0.2.0 增加可与小窗切换的学习中心大界面，用于设置和查询“任务 → 学习段 → 聊天”；每段独立保存，旧聊天按原会话保留。历史浏览不改变当前对话上下文，详见 [任务归档与大界面](task-archive.md)。
- 拖拽与点击交互需要区分，拖拽结束不误触打开聊天；聊天小窗与桌宠共用同一角色会话和学习状态。
- 提供内置角色，也支持用户导入动画资源包；缺少动作时回退到待机。
- 人设、动画资源与声音配置分别关联。
- 用户文字输入，宠物显示文字并可语音播报；首版不包含语音输入。
- 自动播报提醒和聊天，包括休息主动开场；计时与连接状态等通知显示文字。
- 只播报角色说话内容，动作描写与旁白保留为文字并配合已有动画。
- 角色回复文字流式展示，整条回复完成后提取角色说话内容交给 TTS；不在文字生成中途开始合成或播报，动作与旁白保留为文字。
- 仅使用用户配置的 TTS；未配置或调用失败时保留文字，不使用系统语音兜底。
- 电脑端播放聊天语音时，提醒语音等待当前语音结束，不立即打断；开始播报前重新检查观察时效、行为状态、用途豁免与学习状态，只有提醒仍有效时才播报，失效时取消待播音频。已显示的文字提醒与已用额度按已发送状态处理。
- 同时支持在线与本地 TTS，以及已有音色选择和参考音频定制。
- 在线 TTS 确定采用小米 MiMo API；本地确定采用 GPT-SoVITS，由用户自行部署服务。

## 6. 模型与拟定模块分工

- 视觉和对话分别配置，可复用相同服务与模型。
- 首轮视觉服务确定为 DeepSeek；官方当前图像模型 `deepseek-flash` 是建议验证配置，实际能力需通过真实画面测试。
- 角色对话也采用 DeepSeek，由 SillyTavern 管理角色与对话上下文；具体对话模型待确定。
- MiMo 预置音色对应 `mimo-v2.5-tts`，参考音频对应 `mimo-v2.5-tts-voiceclone`；需实现并验证专用适配器。
- GPT-SoVITS 官方 API 与 SillyTavern 适配器接口不可直接假设相同，需选定并验证适配方式。

建议分工：

| 模块 | 职责 |
| --- | --- |
| 桌面程序 | 宠物窗口、设置、任务计时、采集、状态展示 |
| 视觉分析 | 接收带来源和时间的画面，输出结构化观察与不确定信息 |
| 提醒控制 | 维护计时、提醒额度、手机用途豁免与聊天轮数 |
| SillyTavern 桥接 | 注入必要观察摘要、调用角色生成、同步用户对话与回复 |
| Telegram 桥接（拟定） | 绑定用户私聊、接收手机消息、调用同一角色会话、发送休息开场和回复 |
| TTS 适配与播放 | 区分台词和旁白、调用 MiMo 或 GPT-SoVITS、播放与停止音频 |
| 本机记忆 | 摘要管理、纠错、删除、备份与迁移 |

人设控制表达，提醒控制模块执行规则；角色生成不直接修改计时、额度或已确认的事实。

## 7. 首轮原型安排

- 首轮优先验证角色对话与桌宠表现；用户摄像头约三天后到货，实际摄像头观察与行为提醒效果放到后续设备到位时验证。
- 原型先贯通内置 SillyTavern 运行环境、DeepSeek 角色对话、2D 状态动画与用户配置的 TTS；首轮在本机使用用户提供的 V3 角色卡和狐狸素材验证。公开源码不包含角色卡、世界书内容及私人素材导入记录，使用者需自行准备本地角色卡。
- 摄像头缺席期间不以模拟结果声称完成真实视觉效果验证；最终首版的多屏/摄像头、提醒、Telegram、资料与记忆功能范围保持原设计。
- 首轮验收已确认：狐狸透明置顶、拖拽、自动眨眼与点击聊天小窗；现有 V3 角色卡及 8 条世界书在实际对话中生效；DeepSeek 流式回复与 MiMo TTS、播放状态联动；按钮或明确消息控制学习开始和结束，记录有效时长并进入休息。
- 2026-10-13 已实现首轮原型，代码与运行说明见项目 `README.md`。固定 SillyTavern 1.19.0，另行内置经官方 SHA256 验证的 Node 24.14.0，绕开 Electron Node 环境不支持 `shake256` 的兼容问题。酒馆真实前端负责生成上下文，未修改上游源码。
- 使用实际酒馆和本机模拟模型/TTS 接口验证了 8 条世界书完整进入请求、流式显示、完整回复后台词合成和说话状态；真实 DeepSeek/MiMo 效果尚待用户配置密钥后验收。记录见 `integration-report.json`，打包验证另记 `packaged-integration-report.json`。
- 本原型不提供摄像头、多屏观察、5/10/15 分钟行为提醒、Telegram、资料库、长期摘要或 GPT-SoVITS；这些仍属于后续首版范围。学习 30 轮提醒已与行为额度分开实现。
- API 密钥使用 Windows 加密保存，酒馆仅持有当次运行的本机转发令牌。学习快照每 15 秒及退出前保存；退出后重新启动恢复为暂停，系统唤醒恢复规则保持原约定。
