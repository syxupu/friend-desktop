# 旧学习结束通知错位（0.1.5）

现象：连续聊天两轮后，聊天末尾出现“本段学习结束”“任务已结束”，看起来像系统刚刚结束学习。用户确认顶部状态和计时并未停止。

诊断时，本机快照为 `mode: study`、`segment: 3`、`rounds: 2`，30 轮提醒标志为 false。旧结束通知和新学习开始通知都仍在同一进程的消息数组中。

根因：0.1.4 的 `configure` 和 `replaceHistory` 刷新酒馆历史时，使用“全部酒馆消息 + 全部本机通知”的拼接方式，把以前的状态通知统一移动到末尾。触发点包括完整回复返回、重新生成、编辑/删除消息及保存设置重新配置。学习状态机并未自动结束学习。

修复：两条刷新路径统一使用 `src/chat-history.ts` 的 `mergeChatHistory`。根据通知前后仍存在的消息 ID 保留其对话位置，新生成消息的临时 ID 被规范 ID 替换时以原会话位置作为回退。新增通知带有发生时间，并在界面显示。未更改学习结束条件或 30 轮提醒规则。

验证：37 项自动化检查通过；`tests/chat-history.test.ts` 覆盖旧结束/新开始通知、连续两轮、重新配置、编辑、重新生成和删除锚点。`node scripts/chat-controls-integration.mjs --packaged --notices-only` 使用独立数据和本机模拟 API，先建立旧结束通知，再开始新学习段并完成两轮，断言顶部状态仍为学习、计时增长、旧通知位于新对话之前且显示时间，同时回归历史编辑、删除及重新生成。成品结果见 `notice-order-validation.json`；此次专项不包含置顶验证。

用户原始聊天、人设、世界书和学习数据未为此重置。0.1.5 输出在独立目录，需退出旧版后使用。
