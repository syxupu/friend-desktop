更新日期：2026-10-18。本文供在另一台电脑上的 Codex 或其他开发者接手使用。

- 技术路线：Electron 41 + TypeScript；固定 SillyTavern 1.19.0，提交 `7e8663cd9c184a550b37238218bdd32c6efc68e9`；内置 Node.js 24.14.0 Windows x64。

- 仓库不含私人角色卡、世界书内容、API 密钥、用户聊天、测试数据与已有安装包。原机文件仍留在原机，没有随 Git 迁移。

## 2. 新电脑从零运行

使用 Windows 10 / 11 x64。开发机安装 Node.js 24、npm、Git 和 PowerShell 7。原生组件需要 Windows .NET Framework x64 编译器；集成测试另需 Edge。当前构建脚本会拒绝在非 Windows 系统构建窗口读取器。

```powershell
git clone https://github.com/syxupu/friend-desktop.git
Set-Location -LiteralPath friend-desktop
npm ci
npm run setup
npm run typecheck
npm test
```

`npm ci` 根据锁文件安装开发依赖；`npm run setup` 下载固定酒馆版本并校验 Git 提交，安装酒馆生产依赖，再下载官方 Windows Node 包并校验 SHA256。需要访问 GitHub、npm 与 Node.js 下载站。首次启动酒馆需要编译其前端。

启动前，私下复制或准备自己的 **SillyTavern V3 JSON** 角色卡，放到 `assets/characters/主人的猫.json`。这是现有兼容路径，不要求使用特定人设，卡内需要标准 V3 字段（包括 `data.name`）。PNG 卡先用可信工具导出 V3 JSON；不要把任何私人卡强制加入 Git。只做源码阅读、类型检查和单元测试不需要角色卡。

```powershell
npm start
```

打开“学习中心 → 陪伴设置”，分别填写自己的 DeepSeek 和 MiMo 地址、模型及密钥。当前代码的默认模型名来自原型配置，不保证账户当前可用，需按服务方和账户实际情况配置。真实接口调用会产生用户账户费用，日常自动检查使用本机模拟接口。

开发依赖与运行依赖都准备好后，可执行 `npm run package`，输出 `release/0.2.0/win-unpacked/`。成品需要整个目录，不能只拷贝 exe。**打包会包含本机角色卡，现有产物不能直接作为公开发行包上传。**

## 4. 已确认且应保留的产品规则

### 学习与聊天

- 按钮和用户完整指令控制状态：`开始学习`、`暂停学习`、`继续学习`、`结束学习`、`结束任务`。普通聊天和角色回复不得改变状态；不按固定倒计时自动结束。
- “结束本段/结束学习”进入休息：保存该段后清空小窗，随后休息交流仍归入此段；休息主动开场一次，用户不回应不连续追问。
- “结束任务”结束整个任务，立即清零当前显示时长并清空小窗；历史归档仍保留。下一次开始新任务，而休息后开始下一段仍属于原任务。
- 历史按“任务 → 学习段 → 聊天”查看。学习与休息可共用段上下文，但小窗在结束本段时隐藏此前学习消息；不要误删酒馆原文件来实现清屏。
- 一次用户发言和一次完整角色回复计 1 轮。每学习段达到 30 轮只提醒回去学习一次，不自动结束；取消、不完整、自动开场和重新生成不额外计轮。
- 系统睡眠/休眠暂停，唤醒自动继续同一段；手动暂停仍保持暂停。应用退出重启则恢复为暂停，不把离线时间计入学习。锁屏本身不暂停计时。
- 用户曾要求删除当前角色开场白且重启后不再加载。本机卡已处理，但私人卡不在仓库；不能据此声称任意用户导入卡都自动清空全部开场字段。新段空会话逻辑在桥接层；更换卡及重启后应回归检查，避免擅自恢复旧开场。休息主动开场是另一个明确保留的产品行为。

### 观察与行为提醒（以下尚待实现）

- 用户优先要求减少误提醒；观察事实、模型推断和用户确认必须区分。不清晰、遮挡、失联或 API 失败不能当作娱乐证据。
- 摄像头观察桌面、纸质试卷、双手和手机；允许外接摄像头与机位调整，无摄像头允许仅桌面模式。经用户启用权限后允许把画面发给其配置的云端服务；默认不保存自动采集的原始画面。
- 原方案为每 30 秒分析所有屏幕与摄像头；后续方向是前台应用与标题规则优先、混合用途再按需分析，避免无条件调用。当前仅完成窗口读取；未知应用默认策略、摄像头频率及变化检测需要继续确认，不得假定已经批准全套调度实现。
- 学习时观察；暂停、休息、任务结束停止。锁屏继续计时及摄像头观察、停止桌面采集，是目标规则；当前窗口读取在锁屏时停止，摄像头仍未实现，实际锁屏采集能力待设备验证。
- 两路待提醒行为统一连续计时，不重复叠加手机/电脑时长；同一段共用最多 3 次，等待阶段依次为 5、10、15 分钟。行为持续不中断时在第 5、15、30 分钟提醒。
- 确认两路行为均停止后，当前等待计时归零，但已用额度保留；切换手机和电脑娱乐不重启连续计时。观察中断或不能确认时暂停行为计时，恢复有效观察后重新计当前等待阶段，不拼接中断时长。
- 手机用途不明可先按人设温和询问。用户明确说明用于学习，立即豁免本次连续手机使用，放下手机后豁免结束；不形成永久白名单，不豁免同时存在的电脑娱乐。
- 已发出后被纠正的提醒仍占用额度，标记为已纠正；判断有效但角色 API 生成失败时可用内置文字提醒，判断无效时不能借此发提醒。
- 视觉结果按拍摄时间判断有效期，超过 60 秒不用于即时提醒；新观察优先，旧段/旧状态回包不得覆盖新状态。暂停、休息、行为停止等事件取消尚未发出的提醒。
- 聊天语音正在播放时提醒等待，实际播放前重新检查有效性；失效则取消，不能只在入队时检查。聊天 30 轮提醒不占用行为提醒的三次额度。

### 未来渠道与记忆

- Telegram 使用用户自带 Bot，休息文字与可开关语音通过手机交流；允许手机明确指令开始新学习段，同步电脑权威状态并重置新段额度/轮数。未配置或失联回退电脑端；开场、命令和回复需去重。
- 休息保持运行与可关闭的避免自动睡眠设置；实际睡眠期间桌面程序无法实时处理手机消息。当前只有本机保持清醒能力，没有 Telegram 收发。
- 学习主题、进展、难点跨角色共享；各角色私人交流与约定分别保存。长期摘要应可查看、纠正、删除，不把不确定观察存成事实。
- 资料入口目标为文字、图片、PDF、Markdown、Word `.docx`/`.doc`，电脑和 Telegram 均支持。指定章节只分析指定范围，未指定覆盖全文；默认保留用户提交原文件。
- 删除资料默认同时删除关联摘要、索引和记忆，提供“仅删除原文件”。数据本机保存，备份默认排除 API 密钥。
- 语音仅播报说话内容；角色文字先流式、完整后 TTS，不使用系统语音兜底。在线 MiMo、本地 GPT-SoVITS、参考音频定制为后续适配范围。

## 8. 私人数据、换机与 Git 工作方式

正常数据目录是 `%APPDATA%/friend-desktop/`：`settings.json` 保存加密密钥，`session.json` 保存学习快照，`chat-library.json` 保存索引，`tavern-data/` 保存酒馆角色和 JSONL 聊天。继续写代码无需迁移它们。若要保留用户历史，先退出软件并私下备份整个目录，再单独规划迁移；不要只搬索引而遗漏原会话。加密密钥依赖 Windows 用户，新电脑需要重新配置。

`vendor/`、`node_modules/`、`dist/`、`release/`、私人素材及测试数据被忽略是有意设计；无需把它们补传。`.gitignore` 对 `docs/` 使用逐文件允许规则，新增交接或开发文档时增加明确例外，不整体开放截图、原始报告与私人材料。
